openoms ships as one `oms` binary. Install it with one command, or build it from source.

## Overview

`oms` is a single executable: the server, the web cockpit and the command-line tool in one
file. It needs no runtime, and the cockpit is embedded. Its only outside dependency is a
PostgreSQL 16 database, which [`oms init`](/openoms/getting-started/) can start for you in
Docker.

## Installation

<Tabs syncKey="os">
<TabItem label="macOS & Linux">

```sh
curl -fsSL https://maxkuttner.github.io/openoms/install.sh | sh
```

<Aside type="note" title="Supported systems">
macOS on Apple Silicon (M1 or newer), and Linux x86_64 with glibc and OpenSSL 3, as on
Ubuntu 22.04, Debian 12 or newer. Ubuntu 20.04, RHEL 8 and Amazon Linux 2 ship OpenSSL
1.1, and Intel Macs have no prebuilt binary: [build from source](#build-from-source)
there.
</Aside>

</TabItem>
<TabItem label="Windows">

<Aside type="caution" title="To be implemented">

</Aside>

</TabItem>

The install script downloads the latest release for your platform, checks it against the
release's `SHA256SUMS`, and puts it in `~/.local/bin`. It needs no sudo and starts
nothing. [Read install.sh on GitHub](https://github.com/maxkuttner/openoms/blob/main/install.sh)
before you pipe it into a shell. When it finishes, it offers to run `oms init`.

To check that `oms` was installed:

```sh
oms --version
```

### Add oms to your PATH

If `oms --version` says `command not found`, `~/.local/bin` is not on your `PATH`.

<Tabs syncKey="os">
<TabItem label="macOS & Linux">

<Steps>

1. Add the directory to your shell profile: `~/.zshrc` for zsh (the macOS default),
   `~/.bashrc` for bash (most Linux distributions):

   ```sh
   echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
   ```

2. Open a new terminal and check:

   ```sh
   oms --version
   ```

</Steps>

</TabItem>
<TabItem label="Windows">

Inside WSL 2, follow the **macOS & Linux** tab with `~/.bashrc`.

</TabItem>
</Tabs>

### Build from source

For any other platform. You need Rust (stable), cmake with a C++ compiler (the embedded
FIX engine is C++), OpenSSL 3 (`brew install openssl@3` on macOS) and Node 22 for the
cockpit.

```sh
git clone https://github.com/maxkuttner/openoms.git && cd openoms
(cd cockpit && npm ci && npm run build)   # build the cockpit first: it is embedded
cargo build --release
cp target/release/oms ~/.local/bin/
```

A binary built without the cockpit bundle serves a 404 at `/cockpit/`.

## Upgrading

Once installed, `oms` upgrades itself:

```sh
oms update
```

`oms update --check` only reports whether a newer release exists. A source build refuses to
overwrite itself: run `git pull` and rebuild instead. After upgrading, apply new database
migrations; see [Updating](/openoms/operations/updating/).

## Installing older versions

<Tabs syncKey="os">
<TabItem label="macOS & Linux">

```sh
curl -fsSL https://maxkuttner.github.io/openoms/install.sh | OMS_VERSION=v0.4.0 sh
```

</TabItem>
<TabItem label="Windows">

Inside WSL 2, use the **macOS & Linux** command.

</TabItem>
</Tabs>

From source: `git checkout v0.4.0`, then build as above.

An installed `oms` can also move to a specific release, older or newer:

```sh
oms update --version v0.4.0
```

## Direct downloads

Every release is on the
[GitHub releases page](https://github.com/maxkuttner/openoms/releases). Download a
tarball, check it against `SHA256SUMS`, and put `oms` on your `PATH`.

## Requirements

| Platform | Architecture | Minimum |
|---|---|---|
| macOS | Apple Silicon (arm64) | macOS on M1 or newer |
| Linux | x86_64 | glibc and OpenSSL 3 (Ubuntu 22.04, Debian 12 or newer) |
| Anything else | any | build from source |

The server also needs PostgreSQL 16, either your own or one `oms init` starts in Docker.

## Uninstall

<Tabs syncKey="os">
<TabItem label="macOS & Linux">

```sh
rm ~/.local/bin/oms
```

</TabItem>
<TabItem label="Windows">

Inside WSL 2, use the **macOS & Linux** command.

</TabItem>
<TabItem label="Package Managers">

Not available yet: see [Installation](#installation).

</TabItem>
</Tabs>

This leaves your configuration and data. To remove those too:

```sh
rm -r ~/.config/oms                                       # config and master key
docker rm -f oms-postgres && docker volume rm oms-pgdata  # only if oms init started Postgres in Docker
```

<Aside type="caution">
Deleting `~/.config/oms` deletes the master key. Without it, the broker credentials stored
in the database cannot be decrypted. Removing the `oms-pgdata` volume deletes the
database.
</Aside>
