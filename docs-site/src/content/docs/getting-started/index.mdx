openoms is a single `oms` binary: the server, the web cockpit and the command-line tool in
one file. Four steps take you from nothing to a logged-in cockpit.

## 1. Install

Pick your system. The choice is remembered on every page of these docs.

<Tabs syncKey="os">
<TabItem label="macOS">

Apple Silicon (M1 or newer):

```sh
curl -fsSL https://maxkuttner.github.io/openoms/install.sh | sh
```

The binary lands in `~/.local/bin`, which is not on the default macOS `PATH`. If the
installer says so, add it to `~/.zshrc` and open a new terminal:

```sh
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
```

For the Docker database option in the next step, install and start
[Docker Desktop](https://www.docker.com/products/docker-desktop/). Not needed if you
already have a PostgreSQL 16.

</TabItem>
<TabItem label="Linux">

x86_64, glibc as on Ubuntu 22.04 / Debian 12 or newer, with OpenSSL 3:

```sh
curl -fsSL https://maxkuttner.github.io/openoms/install.sh | sh
```

If `~/.local/bin` is not on your `PATH`, the installer prints the line to add. Put it in
`~/.bashrc` and open a new shell:

```sh
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
```

Ubuntu 20.04, RHEL 8 and Amazon Linux 2 ship OpenSSL 1.1 — use the **From source** tab
there.

For the Docker database option in the next step, install
[Docker Engine](https://docs.docker.com/engine/install/) and let your user run it without
sudo:

```sh
sudo usermod -aG docker "$USER"   # then log out and back in
```

</TabItem>
<TabItem label="From source">

For any other platform. You need Rust (stable), cmake with a C++ compiler (the embedded
FIX engine is C++), OpenSSL 3 (`brew install openssl@3` on macOS) and Node 22 for the
cockpit.

```sh
git clone https://github.com/maxkuttner/openoms.git && cd openoms
(cd cockpit && npm ci && npm run build)   # build the cockpit first: it is embedded
cargo build --release
cp target/release/oms ~/.local/bin/
```

A binary built without the cockpit bundle serves a 404 at `/cockpit/`. Source builds
update with `git pull` and a rebuild; `oms update` refuses to overwrite them.

</TabItem>
</Tabs>

The installer downloads the latest release, checks it against the release's `SHA256SUMS`,
and installs it — no sudo, nothing configured, nothing started.
[Read install.sh on GitHub](https://github.com/maxkuttner/openoms/blob/main/install.sh)
before you pipe it into a shell. When it finishes it offers to run `oms init` for you.

```sh
oms --version
```

## 2. Set up

```sh
oms init
```

It asks three things. Arrow keys choose, Enter takes the default:

```text
? Database
❯ Start PostgreSQL 16 in Docker for me   (Docker found)
  Use an existing PostgreSQL 16
? Cockpit admin password (Enter = generate)
? Listen on (localhost:3001)
```

| Question | What your answer does |
|---|---|
| **Database: Docker** | Starts `postgres:16` as container `oms-postgres` (data in volume `oms-pgdata`), reachable only from this machine. If port 5432 is taken it uses the next free one and says so. |
| **Database: existing** | Asks for host, port, database name, and a superuser login. The superuser password is used once, to create the database and the `oms` role, and never stored. |
| **Admin password** | Your cockpit login, at least 12 characters, typed twice. Press Enter instead and one is generated and shown at the end. |
| **Listen on** | Where the cockpit and API listen. Keep `localhost:3001` and reach a remote server through an SSH tunnel or Tailscale; `0.0.0.0:3001` exposes it to the network, and `oms init` warns you. |

Then it writes `~/.config/oms/oms.toml` (mode `0600`), creates the database, applies every
migration and loads reference data (currencies, ~2,800 venues, trading calendars).

<Aside type="caution" title="Back up oms.toml">
The master key in `oms.toml` is the only thing that can decrypt the broker credentials you
store later. Lose it and they are gone. See
[Master key and backups](/openoms/operations/master-key-and-backups/).
</Aside>

`oms init` refuses if a config already exists in any
[location it searches](/openoms/configuration/file-locations/). To upgrade an existing
database, use `oms database migrate` — with a Docker database, see
[Updating](/openoms/operations/updating/) for where its superuser password lives.

## 3. Start

```sh
oms
```

It logs what it found and listens where you told it. On a fresh install, expect a note that
the instrument catalog is empty — the cockpit fills it in the next guide.

## 4. Open the cockpit

Open `http://localhost:3001/cockpit/` and log in with your
admin password. On a remote server, tunnel the port first:

```sh
ssh -L 3001:localhost:3001 your-server
```

Forgot a generated password? It is `admin_password` in `~/.config/oms/oms.toml`.

**Next:** [your first paper trade](/openoms/getting-started/first-paper-trade/) — connect
Alpaca paper in the cockpit and send one share of AAPL.

<details>
<summary>Scripted installs</summary>

The installer reads:

| Variable | Default | Effect |
|---|---|---|
| `OMS_VERSION` | `latest` | Release tag to install, e.g. `v0.4.0` |
| `OMS_INSTALL_DIR` | `$HOME/.local/bin` | Where the binary goes |
| `OMS_NO_INIT` | unset | `1` skips the "Run oms init now?" question |

With no terminal attached (CI, provisioning tools) it never asks.

`oms init --non-interactive` asks nothing and takes every answer from flags or the
environment:

| Flag | Environment | Default |
|---|---|---|
| `--postgres docker\|existing` | — | `existing` |
| `--host`, `--port`, `--database`, `--username`, `--password` | `POSTGRES_HOST`, `POSTGRES_PORT`, `POSTGRES_DATABASE`, `POSTGRES_USERNAME`, `POSTGRES_PASSWORD` | `localhost`, `5432`, `ods`, `postgres`, `postgres` |
| `--admin-password` | `OMS_ADMIN_PASSWORD` | generated, written to `oms.toml`, never printed |
| `--bind` | `OMS_BIND_ADDR` | `localhost:3001` |

```sh
oms init --non-interactive --postgres docker --bind localhost:3001
```

The same flags work interactively: each one given skips its question.

</details>
